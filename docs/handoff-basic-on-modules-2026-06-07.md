## The budget wall (why ADDR-table relocation is next)

The ext-ROM track relocates handlers INTO main. COPPER cost main **+373 bytes**; main is at **390
free** ($3E51 / $3FD7). The next domain (blitter/dma) overflows. The FINAL ext-ROM elimination must
fold the **residual** (math copro, BITSET, **ADDR + `runtime_labels.inc` table ~700–900 B**) into main
— which won't fit. **User decision (2026-06-07): move the ADDR table OUT of ROM next**, so it leaves
the residual and frees the endgame.

## How ADDR() works today (to relocate)

- `ADDR("LABEL")` → `EXT_ADDR` handler in `ehbasic/extension.s` → `ext_label_hash` → index into
  `RuntimeLabelBuckets` (64 buckets) → walk bucket chain (entry = len byte + 16-bit value + name
  bytes), compare name, return the 16-bit address.
- The hash table is `ehbasic/runtime_labels.inc` (`.include`d at `extension.s:~2071`), **generated by
  `tools/gen_runtime_abi_docs.py`** from the runtime `.inc/.s` + `basic.sym` (see the `gen_runtime_abi_docs.py`
  exec in `e6502.Avalonia.csproj` ~line 87). 105 entries now (was 124; shrinks as routines modularize —
  but the MMIO register labels stay, so it stays large).
- Both `EXT_ADDR` + the table live in the **extension ROM** today (so they don't consume main yet).

## The plan: relocate ADDR into a module (recommended) — design THIS first

Make `ADDR("X")` a `lib_call` lookup against a table that lives in a **module**, not the ROM:
1. **Where the table lives — DESIGN DECISION (brainstorm first):**
   - (rec) A module fn, e.g. extend the **SYSTEM module** ($03) or a small new module, with a
     `SYS_ADDR_LOOKUP` fn: marshal name ptr/len (ARG0 ptr, ARG1 len — or the NET packed-ARG0 style)
     → wrapper hashes + searches the table (data baked into the module's 16KB) → `LIB_RESULT` =
     address. Move `runtime_labels.inc` generation to emit into the module source instead of ext ROM.
   - vs host-loaded (FIO/host lookup) — adds a round-trip; the table would live on SD/host. Probably
     worse than a module (modules are the established pattern).
   - Check the SYSTEM module's free space (`modules/system/system.bin` / map) to confirm the table fits.
2. **BASIC side:** `ADDR` token handler in main marshals the name → `lib_call(SYSTEM, SYS_ADDR_LOOKUP)`
   → reads `LIB_RESULT`. Remove `EXT_ADDR` + the `runtime_labels.inc` include from `extension.s`;
   neutralize its ExtTable slot. The table no longer burdens main OR the ext-ROM residual.
3. **Generator change:** `tools/gen_runtime_abi_docs.py` currently writes `runtime_labels.inc` for the
   ext ROM. Repoint it to emit the table into the module source/build. Keep `runtime_labels.json` +
   the md docs.
4. **Verify:** ADDR("VGC.CMD"), ADDR of a still-resident label, etc. still resolve. Full suite green.
   Note ROM deltas: ext ROM should drop by ~700–900 B (table) + the EXT_ADDR handler.
