# NovaZ Z6 M1 — V6 Boots, Text Only — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A Version 6 story boots through the Nova runtime, calls its main routine, prints text through a minimal 8-window model, and reaches a read prompt — with a generated `test-z6-spec` smoke guarding every piece, and Zork Zero reaching its first prompt.

**Architecture:** ROM-side changes (version gate, packed-address offsets, main-routine startup, dispatch trampolines) stay in `novaz.bin` ($C000). All V6 window/EXT logic lives in a new RAM-resident segment `NOVAZ6.BIN` loaded at `$2000` by the runtime when the story is V6. Tests are generated synthetic stories run through the existing headless smoke harness (`Nova.NovaZ.Smoke`), exactly like `test-z5-spec`.

**Tech Stack:** ca65/ld65 (65C02), C# generator/packer tools, `make -C examples/novaz` targets.

**Working directory:** everything below is relative to `examples/novaz/` in the `novaz-z6` worktree (`/Users/barry/Git/e6502/.worktrees/novaz-z6`). Run all `make` from repo root as `make -C examples/novaz <target>`.

**Design doc:** `docs/plans/2026-06-09-novaz-z6-design.md` — read it first.

**Key reference facts (verified):**
- Version gate: `src/zstory.s` `zstory_validate_version` (~line 224) accepts 1–5.
- Packed unpack: `src/zvm.s` `zvm_unpack_operand_packed_addr` (~line 1076): computes `2P`, then doubles for v4+ → `4P`. Callers: `zvm_call_common` (~line 1000), `print_paddr` (~line 1129), and `nz_call_z_routine` (~line 3843) for sound/timed routines.
- Startup: `zvm_run_until_read` (~line 255) loads `zstory_initial_pc_lo/hi` directly into `zvm_pc_*`.
- EXT dispatch: `zvm_dispatch_ext` (~line 659) bounds-checks against `zvm_ext_count`; table `zvm_ext_table` (~line 4767) has 11 entries.
- Branch helpers: `zvm_branch_decode`, `zvm_branch_apply`, `zvm_branch_true`, `zvm_branch_false` (~line 1188 area). Every branching stub must use these so the branch byte(s) are consumed.
- Boot flow: `src/runtime.s` `reset` → `zstory_load_default` → `zstory_read_header` → `@header_ok:` → `nz_sound_preload` → `init_game_screen` → `zvm_run_until_read`. Error pattern: `LDA #<msg / LDY #>msg / JSR print_line / BRA halt`.
- FIO: `fio_copy_name` + `fio_load` stream a named NDI file into XRAM at `FIO_ARG_ADDRL/M/H`. XRAM readback: set address via `zstory`-style helpers or the `xram` lib (`xram_read8`, `XRAM_DATA` port auto-increments).
- RAM: BSS is `$0300–$1866`. `src/runtime.cfg` RAM region currently `start $0300, size $BD00`.
- Packer already supports `--asset "<path>:<NDI name>"` — no packer changes needed to ship `NOVAZ6.BIN`.
- Smoke harness: `--expect-screen <text>` (whitespace-normalized substring), `--script <file>`, auto-handles `[ MORE ]`. Spec-story Makefile targets are the model: copy the `test-z5-spec` rule shape (Makefile ~lines 129–142).
- `Z5SpecStory` (`tools/Nova.NovaZ.Z5SpecStory/Program.cs`, 1047 lines) is the generator to clone: `ZCode` builder (`OneOp`/`TwoOp`/`VarOp`, `Operand.Large/Small/Var`, label+branch+packed-address patching with `packedAddressScale`), `ZString` encoder, hardcoded memory-layout constants, `AssertVarEquals` pattern.

**V6 spec facts the implementer must not guess (Z-Machine Standard 1.1):**
- Packed routine address → byte address: `4P + 8×R_O` where `R_O` = word at header `$28`. Packed string: `4P + 8×S_O`, `S_O` = word at `$2A`.
- Header `$06` in V6 is the **packed address of the main routine**, not a raw PC. It is called with no arguments; if it returns, the machine halts.
- V7 also uses offsets, V8 uses `8P` — both stay **unsupported** (gate accepts 1–6 only).
- V6 window properties 0–15: y-coord, x-coord, y-size, x-size, y-cursor, x-cursor, left margin, right margin, newline-interrupt routine, interrupt countdown, text style, colour data, font number, font size, attributes, line count. Coords/cursors are 1-based **units**; we declare 1 unit = 1 gfx pixel and font 4×4, so text cell col = `(x_units-1)/4`, row = `(y_units-1)/4` (see design doc).
- Window attributes (prop 14): bit 0 wrapping, bit 1 scrolling, bit 2 transcript, bit 3 buffered. Window 0 default: all set except transcript. Windows 1–7 default: none.
- `erase_window` V6: operand −1 = reset windows + clear; −2 = clear all, windows untouched; n = clear window n only.
- EXT opcodes: 5 `draw_picture`, 6 `picture_data` (BRANCHES if data valid; with no pictures: for N>0 branch false; for N=0 write word0=count(0), word1=release(0), branch false), 7 `erase_picture`, 8 `set_margins`, 16 `move_window`, 17 `window_size`, 18 `window_style`, 19 `get_wind_prop` (STORE), 20 `scroll_window`, 21 `pop_stack` (STORE), 22 `read_mouse`, 23 `mouse_window`, 24 `push_stack` (BRANCHES on success), 25 `put_wind_prop`, 26 `print_form`, 27 `make_menu` (BRANCHES), 28 `picture_table`, 29 `buffer_screen` (STORE).
- User stacks (24/21): a user stack is a Z-memory table whose word 0 holds the number of free slots; `push_stack value stack` decrements free count and stores, branching on success; `pop_stack items stack` (note: 21 is `pop_stack items stack` — pops and DISCARDS `items` entries, it does NOT store... **correction**: EXT:21 in V6 is `pop_stack items stack?` which throws away `items` entries; the value-popping form is `pull stack` VAR:9 with an operand in V6). Implement: `push_stack` per spec with branch; `pop_stack items [stack]` discards items. Also V6 `pull (VAR:9)` takes an optional user-stack operand and becomes a STORE op — **defer the V6 `pull` variant to M2**; the spec story must not use it in M1.
