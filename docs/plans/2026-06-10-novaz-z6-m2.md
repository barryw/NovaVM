# NovaZ Z6 M2 — Real Window Rendering — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** V6 windows render as real rectangles — Zork Zero's banner/playfield layout displays correctly, text scrolls inside its window, and the M1 stale-text/teleporting-text artifacts disappear.

**Architecture:** Three moves, all data-driven by the captured trace: (1) fix the unit system to cells everywhere (the M1 header already advertises 80×50 units/1×1 font; the segment wrongly converts as if units were pixels); (2) drive the existing `vtext` rectangular-region renderer directly from the V6 window property table (windows become vtext regions with origin/size/margins/wrap/scroll), replacing the M1 lower/upper split mapping; (3) implement in-window scrolling + `scroll_window`. Everything else from the capture is de-scoped with evidence.

**Tech Stack:** ca65/ld65 (65C02), NOVAZ6 segment (`src/zvm6.s`), shared vtext layer (`runtime/asm/vtext.s`), C# spec-story/smoke tools, `make -C examples/novaz` targets.

**Working directory:** `/Users/barry/Git/e6502/.worktrees/novaz-z6`, branch `novaz-z6`. Paths below relative to `examples/novaz/` unless noted.

**REQUIRED READING (in order):**
1. `docs/plans/2026-06-10-zork-zero-window-ops.md` — the captured data. Every design choice below cites it.
2. `docs/plans/2026-06-09-novaz-z6-m1.md` — "Key reference facts" + "V6 spec facts" (architecture, ABI, dispatch).
3. `runtime/asm/vtext.inc` (repo root: `runtime/asm/`) — the region ABI: `VTEXT_LEFT/TOP/WIDTH/HEIGHT`, region-relative `VTEXT_CURX/CURY`, `VTEXT_FLAG_WRAP/SCROLL`, region table (`vtext_define_region`/`select`/`store`, `VTEXT_REGION_*` offsets), `vtext_clear_region`, `vtext_scroll_up`.

**Key verified facts:**
- Header (`src/zstory.s`) advertises **80×50 units, font 1×1** — the game computes in CELLS. The segment (`src/zvm6.s`) converts units as pixels (`(unit-1)>>2`), landing everything 4× off (capture finding 1). The design doc's pixel-unit plan is hereby amended: **1 unit = 1 cell**; M3 converts cells→gfx pixels (×4, exact) at the picture-blit boundary.
- Zork Zero's layout (capture, boot seq 15-18): window 1 = rows 1-5 × 80 (banner, non-scrolling), window 0 = 45 rows × 70 cols at origin (6,6) (playfield, scrolling), window 7 = full screen (title). Built with `move_window`+`window_size`; `split_window` never called.
- The stale-text bug dies via window scrolling (vacated rows blanked inside the rect) — the game **never calls erase_line** (finding 3).
- `scroll_window` is load-bearing (the game's page-reset, finding 4). Props 8/9 (newline interrupt) must round-trip but never fire (countdown −1, finding 5).
- ROM↔segment ABI: grow `RUNTIME_ABI_SYMS` in the Makefile for vtext symbols the segment needs; build fails on missing symbols. The ROM's current NovaZ screen code (`zvm_select_active_window`, lower/upper vars, `vtext_clear_region` calls in `src/zvm.s` ~3210-3530) is the M1 split mapping you are replacing for v6 — READ IT FIRST; v1-5 must keep using it untouched.
- Smoke assertions: `--expect-at <col>,<row>=><text>` (0-based cells); capture regen: `make -C examples/novaz capture-z6-trace PROJECT=zork-zero` (bit-deterministic).
- De-scoped for M2, evidence = never called by Zork Zero (finding 8): window_style rendering, buffer_screen/buffer_mode, erase_line, V6 split_window rendering, print_form, make_menu, read_mouse, erase_picture, erase_window −2/n fidelity. They keep their M1 behavior + comments.

**Commit cadence:** every task red→green→commit; z3/z4/z5 suites + `test-z6-suite` green at every commit (v1-5 paths must be bit-stable).

## Risks

1. **vtext is shared with BASIC/editor** — any vtext.s change risks the whole Nova text stack. Prefer segment-side composition; if vtext must change, the full e6502UnitTests suite is the gate and the change needs its own MSTest.
2. **ROM bytes:** ~1.2KB free. The v6 select_active_window branch is small; if ROM grows tight, move logic segment-side (6.3KB free there).
3. **The ROM print path** (`ztext`→`nz_screen`→vtext) may have NovaZ-side wrap/MORE logic layered above vtext (e.g. `nz_auto_wrap`, `nz_more_line_count` in `runtime.s`) that fights region semantics — the Task 2 reader must map this layer first; expect the real work to be deciding which layer owns wrap.
4. **Prologue nondeterminism in re-pinned smoke** — the fireball interlude moves with script shape; pin only stable early turns (the capture script's `!cmd` fire-and-settle mode exists for this).
5. **get_cursor/scroll feedback loop**: the game computes `scroll_window` from `get_cursor` — after Task 1 both are cells; any residual asymmetry shows up as a wrong-by-rows scroll in the Task 5 capture. The capture diff is the detector.
