Logo base-ROM bytes needed to repatriate the turtle (Phase C), and (b) general dedup.
**EhBASIC excluded** (Lee Davison upstream — mature, divergence risk).

- Logo base ROM free now: **647 bytes** (CODE $C000–$F716, RODATA $F717–$FD4F, MONITOR
  $FFD7). Turtle semantics measured at **1,257 bytes** (6510 agent, from listing offsets)

- NovaLogo squeeze recovers **~528 B (low-risk Tier 1+3) to ~668 B (conservative, +Tier 2)**
  → **~1,175–1,315 B free** → turtle fits with margin.
- NDK dedup (~460 B graphics + ~150–180 B system/io) lands in the **graphics MODULE /
  EhBASIC extension**, NOT the Logo base ROM (Logo calls graphics via `lib_call`). Good
  code health + module headroom for future graphics tokens; does not move the turtle budget.

## Implementation log + EMPIRICAL RECALIBRATION (2026-06-05)

**Shipped (commit cb4a020): NovaLogo squeeze +121 B, 647 → 768 free, suite 110/110 green.**
- 3.1 `STZ eval_type` (11 sites): +22 B (estimate was 22 — exact).
- 1.3 `do_lib_call` helper (5 lib_call sites; turtle adapter left for repatriation): +29 B.
- 1.2 `fill_cons_from_eval` helper: **only 3 of the 9 cons sites** are uniform → +70 B
  (NOT the projected ~330 B).

**The audit byte estimates are systematically OPTIMISTIC.** Verifying the real code:
the interpreter interleaves logic into the "duplicated" blocks, so clean factoring
covers a subset, not all sites:
- Cons construction (9 sites): only 5 fill from `eval_*`; of those only 3 are char-identical.
  The rest fill from a **source cell** (730), from the **CPU stack** (1440/1600/1645, with
  post-fill `VAL_LIST` patching), or zero `eval_*` first with distinct `@oom_pop4/6/8`
  handlers. → ~70 B realized, ~74 B more possible with the 2 commented outliers, the stack
  group needs its own helper.
- Car-read (1.2, ~14 sites projected ~120 B): sites read `CONS_CAR_TYPE` then **branch on the
  type** (VAL_LIST/VAL_WORD/number) before reading the rest — they do NOT do a uniform
  4-field read. Clean `car_to_eval` fits far fewer than 14. Realistic ~40-70 B.

**Revised realistic NovaLogo squeeze ceiling: ~250-300 B (not ~668).** Remaining clean-ish
wins: cons outliers (~74), a `car_to_eval` subset (~40-70), `ret_number` tail 2.3 (~20),
2 stack-cons via a second helper (~40). Error-tails 2.1 (~90) is Med-risk (name plumbing on
all dispatch routes) — defer.

**Turtle fit (recomputed, honest):** turtle semantics measured 1,257 B. After the 6510
turtle-review dedup (~190 B) → ~1,050 B; the adapter `logo_adapt_turtle` (~150 B) is
reclaimed when semantics come home (lib_call marshalling replaced by direct handlers built
on `do_lib_call`). Net to add ≈ ~900 B. Free after full realistic squeeze ≈ 647+275 ≈ 920.
**Fit is marginal-but-plausible — only confirmable by doing the move + measuring.** The
existing ext_cmd_table turtle rows (176 B) + ~38 name strings already live in base ROM and
are reused (not re-counted). Recommended next: apply the turtle-code dedup IN the module
first (shrinks the thing being moved), continue the squeeze opportunistically, then do the
move and let the linker confirm the fit.
