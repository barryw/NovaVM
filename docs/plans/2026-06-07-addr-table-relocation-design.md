# ADDR() Table Relocation — Design + Plan

**Date:** 2026-06-07
**Status:** Design validated (user sign-off). Ready to execute.
**Track:** BASIC-on-modules, extension-ROM elimination. Resume of
`docs/handoff-basic-on-modules-2026-06-07.md` (commit `8e4a2bb`) and
`docs/plans/2026-06-06-basic-on-modules-design.md`.

## Why

The ext-ROM track relocates each ext-domain handler INTO main (ext code can't call
`lib_call` — a page-in swaps its own bank). COPPER (Phase 6) cost main **+373 B**; main is now
at **390 free** (`$3E51`/`$3FD7`). The next ext domains plus the final residual fold won't fit.
The biggest movable residual is the **`ADDR("LABEL")` table** (`runtime_labels.inc`, ~700–900 B)
which currently lives in the extension ROM. **User decision (2026-06-07): move the ADDR table out
of ROM next** so the ext-ROM residual shrinks and the endgame fits.

## Decision (locked, AskUserQuestion 2026-06-07)

The table lives in the **SYSTEM module (`$03`)** as a new `lib_call` function, **not** a new
dedicated module. SYSTEM is already pre-staged into the XRAM shelf at boot (works without SD, even
on FPGA), already `.include`d in `basic.asm`, and has **~4.4 KB free** in its ROM band
(`$EEAE→$FFFA`). A new module would add a store id, Makefile, csproj step, and boot pre-staging for
no gain.

## How ADDR works today (to relocate)

- `@xtk_addr` (`ehbasic/basic.asm:4108`): parse string arg (`LAB_IGBY`/`LAB_EVEX`/`LAB_EVST` →
  A=len, X/Y=ptr; `LAB_1BFB` scans `)`) → store `EXT_ARG_LEN/PTRL/PTRH` →
  `LDA #EXT_CMD_ADDR : JSR EXT_vec` → `CPX #0`: miss→`LAB_FCER`, hit→`JMP LAB_AYFC` (A=hi, Y=lo).
- `EXT_ADDR` + `ext_label_hash` (×33 hash, uppercased) + `ext_upper` at `extension.s:170-278`.
  Table `.include "runtime_labels.inc"` at `extension.s:1834`; ExtTable slot is **cmd 23**
  (`extension.s:118`) — the table is **positional** (`ExtTable + 2*ExtCmdId`); neutralize the row
  to `EXT_UNSUPPORTED-1`, never delete it.
- `runtime_labels.inc` (64 buckets, 105 entries; entry = len byte + 16-bit value + name bytes) is
  generated by `tools/gen_runtime_abi_docs.py` `write_asm()` from `$(ABI_SOURCES)` + `basic.sym`
  (`ehbasic/Makefile:46-47`). Values are absolute host addresses (MMIO registers + BASIC-ROM
  routine addresses) — returned as raw data, so correct even though BASIC ROM is unmapped while the
  module is paged in.

## New ABI: `SYS_ADDR_LOOKUP = $11`

`runtime/asm/libsystem.inc`: add the fn id; bump `SYS_FN_COUNT` 17→18.

- **In:** `ARG0` packed (NET style) — `b0/b1` = name ptr, `b2` = name len. (Name lives at `$0900+`
  / EhBASIC Ram_base, above the module BSS band `$0420-$08FF`, so it survives the bank-1 page-in.)
- **Out (hit):** `LIB_RESULT b0/b1` = 16-bit address; `LIB_STATUS = LERR_OK`.
- **Out (miss / len 0):** `LIB_STATUS = LERR_SYS_FAIL` (`$8D`); result ignored.

## Module side (`modules/system/system.s`)

- `.include "runtime_labels.inc"` (placed in CODE/RODATA). Defines `RuntimeLabelBuckets` +
  `RUNTIME_LABEL_BUCKET_COUNT`.
- Add `sys_jtable` row `$11 .word sys_addr_lookup-1`.
- `sys_addr_lookup`: port `ext_label_hash`/`ext_upper`/the bucket walk verbatim, but read the name
  through a **module-ZP** pointer pair (system.cfg ZP band `$A3-$C2`) seeded from `ARG0 b0/b1`, use
  `ARG0 b2` as the length, publish the 16-bit value to `LIB_RESULT`, and set `LIB_STATUS` (OK on
  hit, `LERR_SYS_FAIL` on miss/empty). ~900 B into the 4.4 KB of free SYSTEM ROM.

## BASIC side (`ehbasic/basic.asm` `@xtk_addr`)

- Keep the parse. Replace execution: marshal **without `basic_lib_zargs`** (it clobbers X→`$FF`) —
  `X→LIB_ARG0+0`, `Y→LIB_ARG0+1`, `A→LIB_ARG0+2`, `0→LIB_ARG0+3`.
- `LDA #MODULE_ID_SYSTEM : LDX #SYS_ADDR_LOOKUP : JSR basic_lib_call` (returns A=`LIB_STATUS`,
  Z=OK). `BNE` → `JMP LAB_FCER`. On OK: `JSR basic_lib_result_word` (→ A=hi/Y=lo) → `JMP LAB_AYFC`.
- Drop the `EXT_CMD_ADDR`/`EXT_vec` path.

## Extension ROM

Delete `EXT_ADDR` + `.include "runtime_labels.inc"`; neutralize ExtTable **cmd 23** →
`EXT_UNSUPPORTED-1`. Remove `ext_label_hash`/`ext_upper`/the `EXT_ARG_*`/`addr_*` scratch **only if
ADDR is their sole user** (verify — grep extension.s; keep anything DIR or another command shares).
This reclaims the ext-ROM residual room that was the point of the exercise.

## Build wiring (the risk — nailed down)

Build order is already correct: csproj `BuildBasicRoms` Unix branch runs `make -C ehbasic`
(generates the table) at line 61 **before** `make -C modules/system` at line 68. Windows/CI does
not rebuild modules — it uses committed `Resources/*.bin`.

1. **Generator:** repoint `--asm` output to `runtime/asm/runtime_labels.inc` (so it sits on the
   module include path — system Makefile uses `-I ../../runtime/asm`). Keep `--json`/`--md`. Reword
   the header comment ("extension ROM" → "SYSTEM module").
2. **`ehbasic/Makefile`:** repoint the `--asm` path; **add the relocated inc to the `all:` target**
   (otherwise nothing triggers generation once `extension.o` drops its dep); remove `extension.o`'s
   `runtime_labels.inc` dependency.
3. **`modules/system/Makefile`:** add `$(NOVA_ASM)/runtime_labels.inc` to `system.o` deps.
4. **Rebuild `system.bin` on Mac**; commit it + `Resources/system.bin` + the FPGA/SD module mirror.
   Delete the now-orphaned `ehbasic/runtime_labels.inc` (moved to `runtime/asm/`).
