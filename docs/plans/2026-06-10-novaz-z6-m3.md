# NovaZ Z6 M3 — Pictures on Avalonia — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development) to implement this plan task-by-task. This plan was written for a FRESH session: read the "Required reading" list before Task 0.

**Goal:** Zork Zero draws its real art on the VGC gfx layer — title screens, the parchment playfield border, the banner laid out from genuine picture metrics — from a `PICS.PAK` pre-converted by the Packer; the boot newline-storm and banner garble disappear because the game finally gets real `picture_data` answers.

**Architecture:** Same three-stage shape as the sound work: (1) host-side, the Packer decodes the Blorb's PNGs, quantizes to the VGC's EGA palette, and writes one flat `PICS.PAK` (index + 4bpp blitter-ready bitmaps) into every NDI; (2) the runtime loads only the index into XRAM at boot and answers `picture_data` from it; (3) `draw_picture` streams one bitmap region from the pak via a new offset-capable FIO load into an XRAM bounce buffer and blits it to the gfx layer at the cell→pixel (×4) converted position. Plus the one V6 engine piece pictures unlock: the CR-interrupt countdown (window props 8/9) must actually decrement and fire — it's how Zork Zero releases its drop-cap margins.

**Tech Stack:** C# (Packer: SixLabors.ImageSharp for PNG decode — new NuGet dep, pure managed, CI-safe), ca65 65C02 (segment `src/zvm6.s` + ROM `src/zvm.s`/`runtime.s`), Avalonia `FileIoController` + `VirtualGraphicsController`, `make -C examples/novaz` targets.

**Verified facts to build on:**
- Art source: `.blb` files beside each `.z6` in `/Volumes/Software/Emulation/Infocom/` (read-only archive). The Packer already has `BlorbReader` (sound work) — extend for `Pict` resources.
- VGC: 320×200 gfx layer, 4bpp; `RegPaletteMode` ($A0E9) selects `PaletteModeEga` ($01) vs Nova/C64 ($00) — see `e6502.Avalonia/Hardware/VgcConstants.cs:797`.
- Smoke assertion `--expect-gfx-color <x,y=>hex>` already exists (gfx pixel color) — the natural picture test instrument.
- FIO register surface at $B9A0 (`VgcConstants.FioCmd`, arg regs); current loads stream whole files from offset 0. M3 needs offset+length region loads (index says where each picture lives).
- XRAM staging hole at `$060000` holds the 8KB NOVAZ6.BIN stage at boot (`ZSTORY_XRAM_NOVAZ6_STAGE_*` in `src/zstory.inc`); after the segment copy it is FREE at runtime — reuse `$060000-$067FFF` region for the pak index + a 32KB picture bounce buffer, document the lifetime handoff in zstory.inc.
- `picture_data` currently writes 0/0 + branch false (honest no-pictures). With a pak present it must flip: N>0 valid → write height,width (IN CELLS — see Task 4) + branch TRUE; N=0 → word0=count, word1=release, branch true iff any pictures. Flags1 bit 1 (pictures available) must be set for v6 when the pak loads.
- CR-interrupt props: game arms prop 9 = $FFFF, prop 8 = routine, every refresh. YZIP spec: interpreter decrements prop 9 before each newline printed to that window; at 0, call the prop-8 routine (no args). Frotz quirk for Zork Zero r393: it fires the routine AFTER printing the newline — match Frotz (it's the behavior the shipped game was tuned against). The boot storm (~65.5K newlines) exists BECAUSE the countdown never decrements; with real decrement the storm self-limits.
- `nz_call_z_routine` (zvm.s) is the existing interrupt-routine call mechanism (sound/timed input) — reuse for the CR fire.
- Colours: switching the VGC to EGA palette changes how ALL color indices render, including NovaZ text colors (`ZVM_COLOR_NORMAL = $0C` etc. assume the Nova palette). Task 2 resolves this — it is the one real gray area; do it early.

## Risks / notes for the implementer
1. **EGA palette flip is global to the VGC** — the one change that can regress BASIC/v1-5 visuals. Gate strictly on v6+pak boots and verify RESET restores. Spec fixtures + the z3/z4 style suite (`test-z4-styles` asserts exact color bytes!) are the canaries — if z4-styles breaks, the mode leaked.
2. **ImageSharp NuGet** — first third-party dep in the packer; CI runs Windows (`dotnet test -c Release`), ImageSharp is fine there, but pin a version in the csproj.
3. **picture_data dims in cells (ceil)** is a NovaZ-specific convention consistent with units=cells — if Zork Zero's layout math looks off-by-one in Task 7, revisit rounding (the capture diff + banner positions are the detector).
4. **Blit transparency**: don't build masking until a Zork Zero picture provably needs it (inspect the PNGs in Task 1); the flags bit reserves the bit either way.
5. **ROM budget** ~1.2KB free; prefer segment-side (6KB+ free). Segment BSS 2KB cap — index lives in XRAM, not BSS.
6. The wedge-class lesson from this branch: any variable held across a `JSR` into zobject/zstory/vtext helpers must be audited for callee clobbering (see `feedback_shared_scratch_and_corrupted_pins` memory / the 80589e1 commit message).
